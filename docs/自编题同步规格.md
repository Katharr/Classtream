# 课堂 OJ 自编题同步规格

## 老师怎么用

在教师机的 `teacher/config.json` 中配置一次 `prep_dir`，指向备课项目，例如 `D:\files\备课`。打开教师 OJ 的「题库」会自动同步，也可在该页点击「重新同步」。选题时可同时选择多个标签，候选题必须包含全部选中的标签，已选题继续留在题单中。

## 备课文件

备课时同步维护讲义 Markdown 和每题一份完整 JSON。Markdown 供人阅读，课堂 OJ 递归扫描 `OJ题目/` 下的 JSON 以导入题目。目录包含正式输入和标准输出，仅保存在本机。

首批导入二分篇的八道自编题，来源 ID 为 `eight-algo-04-binary-search/m1` 至 `eight-algo-04-binary-search/m8`。题目 JSON 按来源 ID 存放，例如 `OJ题目/eight-algo-04-binary-search/m1.json`。

| 字段 | 内容 |
| --- | --- |
| `schema_version` | JSON 格式版本，首版为整数 `1` |
| `source_id` | 固定的来源 ID，由讲义 ID 和题内编号组成 |
| `title`、`statement` | 题名和题目描述 |
| `input_format`、`output_format`、`constraints` | 输入格式、输出格式、数据范围和约定 |
| `sample_cases` | 公开样例数组，每项有字符串 `input`、`output` |
| `judge_cases` | 正式测试点数组，每项有字符串 `input`、`output` 及正整数 `score` |
| `time_ms`、`memory_mb` | 每个测试点的时限和内存限制 |
| `tags` | 字符串数组，去除标签首尾空白，按不区分大小写去重 |

来源 ID 在备课目录内唯一，改题名或移文件时保留 ID。路径校验须覆盖非法路径段与越出根目录的文件。生成端写完临时文件后再替换目标 JSON。OJ 保留样例和用例字符串中的换行，输出判定沿用现有文本比较规则。

## 导入与版本

- 来源 ID 对应同一个 OJ 题目 ID。比较解析后的题目内容，题名、题面、样例、限制、标签或正式测试点变化时记录新版。重复同步相同内容时复用版本。
- `judge_cases: []` 显示「待补评测数据」。必需字段缺失、格式错误、重复来源 ID 或超出评测容量时，在教师题库显示具体原因，继续处理其他题。正式测试点通过校验后题目才可布置。
- 整个来源目录暂时不可读时，教师题库提示正在使用上次同步结果，仍可用其中的有效题组新题单。目录可读且确认某题被删除、重复或校验失败时，旧版本继续供已开放题单和历史记录使用，该题暂不进入新题单的候选列表。
- 开放题单时绑定当时最新的有效版本。之后同步的新版本可用于下一张题单。已开放及历史题单的题目列表、题面和提交使用各自绑定的版本。
- 导入题每题满分 100 分。每个正式测试点独立评测，通过获得该点分值，单题得分是各测试点实得分之和。公开样例用于自测。题目版本保存计分规则，已有手建题保留其最高数据组得分规则。
- 学生可以查看已发布的题面、公开样例、标签、每个测试点的判定和得分。正式输入与标准输出保存在服务端。

## 首批验收

1. 从临时备课目录和数据库验收导入。进入题库应显示二分篇全部八题，重复进入后 OJ 题目 ID、数量和版本号保持稳定。按「二分」与「右边界」组合筛选时，只出现同时有两个标签的题。
2. 开放试点题单，提交标准程序和写死公开样例输出的程序。用 Windows 真实评测器验证标准程序通过全部正式点，写死样例的程序得不到满分。用只通过部分测试点的程序验证累加计分，并检查学生接口仅返回测试点判定和得分。
3. 改题名后重新同步，已开放的题单继续使用原版。下一张题单开放时使用新版，历史题单和已有提交仍关联原版。
4. 分别模拟目录暂时不可读、单题文件格式错误和文件删除，验证教师提示、组题资格及旧版本保留规则。

试点采用 1500 ms 和 256 MB。五道查询题在正式压力点使用 `n=100000`、`q=30000`，使输出能通过现有 Windows 评测器的 256 KiB 限制。参考程序另外在评测器外以 `n=q=100000` 核对满规模答案。导入容量需覆盖首批 JSON 中较大的输入字符串，并按评测器实际输出字节限制校验正式测试点。
