# Classtream 中文课堂界面设计方案

日期：2026-10-28。范围：Windows 局域网教学版的学生端、教师端及其完整交互状态。

## 从实际任务出发

课堂软件的价值，是让学生看清老师正在演示什么，并在不懂时顺利提问。教师需要能快速组织一次共享，并知道当前共享是否正常。因此，设计的优化目标是减少进入课堂的步骤、辨认按钮的时间和课堂被误操作打断的机会。

学生通常已经拿到了教师提供的网址；姓名是参与交流所需的最少信息。屏幕内容由老师决定，学生不需要理解显示器、编码质量或帧率。教师则需要管理课堂地址和屏幕权限，低频设备参数可以在需要时展开。

这是根据当前项目的工作方式提出的设计假设；尚未通过真实学生的可用性访谈验证。首轮验收应观察学生是否需要口头解释就能进入、全屏和提问。

| 角色与场景 | 必要任务 | 界面安排 |
| --- | --- | --- |
| 首次进入的学生 | 直接开始观看 | 系统随机分配可爱动物昵称，无需填写姓名 |
| 正在听课的学生 | 看清内容，必要时放大 | 中央大画面；底部常驻“暂停画面”“全屏观看” |
| 有问题的学生 | 发消息或文件 | 顶部文字按钮“课堂讨论”；按需打开侧栏 |
| 准备上课的教师 | 创建课堂，分享地址 | 左侧首先展示课堂名称、创建按钮、固定上课地址 |
| 正在演示的教师 | 确认画面与共享范围 | 中央共享预览；左侧屏幕选择和共享权限 |
| 调整设备的教师 | 修改清晰度、显示选项 | 放入“更多设置”，避免占用日常操作区 |

## 学生端方案

进入课堂：打开固定 `/class` 地址 → 系统随机分配动物昵称 → 观看老师屏幕。不沿用旧的自定义姓名，不提供改名入口。准备 20 种昵称，同一课堂中不重复，超过 20 人时添加数字后缀；刷新、断线重连和多屏观看保持昵称，服务重启后重新分配。

默认收起左侧面板和讨论区，把空间留给教学画面。左侧只保留屏幕选择、课堂成员及在 HTTPS 模式下可用的语音功能；学生不显示清晰度、教师权限或性能统计等管理项。底部优先展示暂停和全屏，放大、缩小、还原、截图仍可直接使用。

讨论区采用熟悉的消息列表和输入框，明确提示“Enter 发送 · Shift+Enter 换行”。表情、附件、分享代码作为次级工具保留，界面不要求学生学习 Markdown。成员、姓名、讨论消息和文件名保持原文，避免误翻译课堂内容。

手机采用抽屉式讨论和课堂面板，画面模式与讨论模式按需切换。390 像素视口已验证没有整页横向溢出；底部工具栏可横向滚动，全屏按钮位于首屏可见位置。手机实际输入法、横屏和不同浏览器的全屏能力仍需真机体验。

## 教师端方案

主路径：登录教师工作台 → 输入课堂名称 → 创建课堂 → 复制上课地址 → 分享给学生 → 保持教师页在线。

左侧按“课堂管理 → 共享屏幕 → 共享权限 → 课堂成员 → 更多设置”排列。教师姓名、画面清晰度、鼠标显示和连接详情属于低频设置，收进“更多设置”。主区域显示“屏幕共享预览”，避免与学生端的称谓混淆。

“创建新课堂”与“复制上课地址”明确分开。已有课堂时重新创建会先提示当前课堂失效，学生需要重新进入；取消后不修改课堂。现有固定地址和账号权限规则继续沿用。

## 统一中文与状态反馈

| 原文 | 中文表达 | 设计理由 |
| --- | --- | --- |
| Session | 课堂 | 使用教学场景里的日常用语 |
| New Link | 创建新课堂 | 准确表达会重置当前课堂的后果 |
| Copy Link | 复制上课地址 | 明确复制的是什么 |
| Monitors | 共享屏幕 | 说明学生能看到的内容 |
| Private | 仅教师可见 / 暂时隐藏屏幕 | 说明实际影响 |
| Pause / Resume | 暂停画面 / 继续观看 | 避免误解成结束课堂 |
| Group Chat | 课堂讨论 | 更贴近提问和教学交流 |

连接中、自动重连、课堂更新、教师离线、被移出课堂、无课堂和屏幕隐藏都有中文说明。需要恢复操作时给出明确按钮；教师密码错误、文件过大、不支持的文件类型等常见错误也显示中文。连接状态同时用文字和颜色表示，暂停时明确显示“画面已暂停”。

## 视觉方案与参考

采用白色操作面板、浅灰背景、蓝色主操作、深色正文。屏幕内容拥有最高视觉优先级，避免在观看页增加统计卡片、装饰图或多层导航。主要按钮保留图标和文字，不依赖猜测图标含义。

参考 [shadcn/ui](https://ui.shadcn.com/docs) 的组件一致性和可定制原则，以及 [Linear 官方界面重设计说明](https://linear.app/now/how-we-redesigned-the-linear-ui) 中减少视觉噪声、整理侧栏与面板层级的思路。这里借鉴视觉和组织方式，使用现有 HTML/CSS/JavaScript 实现，不引入新的框架、在线字体、CDN 或运行依赖，适合离线局域网课堂。

键盘支持包括可见焦点、表单标签、对话框内 Tab 循环和可读取的展开状态。按钮、下拉框等交互元素获得焦点时，不再触发全局快捷键；减少动画偏好也已处理。这些是本轮可访问性改进，尚未进行全面辅助技术认证。

## 下一轮真实学生验收

让 3–5 名未使用过系统的学生独立完成：进入课堂、识别自己的动物昵称、全屏观看、提问和断线恢复。观察是否需要解释、是否误点、是否找到恢复按钮。以“无需教师讲解就能完成”为通过标准，再据此决定是否继续减少工具栏按钮。整班负载和真实设备性能继续采用原项目的真机验收流程。
