# 真机验收单

目标：教师统一入口部署，学生不安装、不导证书、不修改浏览器即可观看。优先使用一台从未安装过本方案证书的学生设备，保持默认浏览器设置，不使用“忽略证书错误”等特殊启动参数。

## 单台学生机（先做这一组）

1. 教师在 `http://127.0.0.1:8000/?host=admin` 登录并保持页面在线，已有课堂且共享权限允许观看。
2. 学生连接教学网络，打开教师启动窗口显示的 `http://教师当前IP:8080/class`。
3. 确认直接出现姓名/观看页，无证书错误页、安装下载要求、麦克风权限请求。
4. 输入姓名；教师打开课件、移动鼠标、输入几行文字，学生应看到连续更新，文字可读。
5. 刷新后能恢复，地址始终为 /class，没有长 token。
6. 教师 New Link 创建新课堂，学生刷新同一短网址后能观看。
7. 教师关闭管理页，学生看到离线提示；教师重新登录、学生刷新后恢复。
8. 学生无麦克风发言区；使用聊天时双方各发一句，测试复制代码。
9. stop.cmd 后停止共享；再次启动并登录后可恢复。

## 另一台教师机复现

Windows 10/11 x64 上解压干净 ZIP，双击 install.cmd；记录自动找到/安装 Python、依赖安装、原生库检查/VC++ 补装、网卡选择、防火墙确认、设置密码与登录是否成功。使用该机自己的学生网址验收。

发布前已在含空格/中文路径的全新虚拟环境中禁用缓存下载全部依赖，安装与 HTTP/HTTPS 回归通过。原教师与学生设备也已由用户确认验收完成；未记录全班负载人数。“无 Python 的全新 Windows 系统首装”和“缺少 VC++ 时的实际系统安装”仍需另一台教师机现场验收，不能以本机虚拟环境测试代替。

## 逐步增加学生数

依次增加到 5、10 台，再到计划班级人数，每级观察 3–5 分钟。先用代码/课件，再测试画面变化较多的内容；记录教师 CPU、网络发送速率、学生清晰度、卡顿与掉线。不要只用静态桌面判断容量。

默认 30 FPS JPEG 流（目标上限），实际以现场为准。卡顿时先降低质量或帧率、优先教师有线联网，再检查 Wi-Fi 负载。

## 失败时记录

- 教师/学生系统、浏览器版本、IP 和接入网络。
- 失败步骤、时间、提示；教师 check.cmd 输出。
- runtime/backend.log，安装失败另看 runtime/install.log。
- 必要时学生 F12 Console / Network：HTTP 下 isSecureContext 为 false、randomUUID 可能不存在是预期，但不应再因调用它而启动失败。屏幕连接应为 ws://教师IP:8080/ws/...。

反馈注明“单台通过 / 全班通过 / 失败步骤”。日志和截图可能含课堂信息，只提供必要内容。
